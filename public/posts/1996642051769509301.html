研究人员可以自由开展任何他们想要的项目，但必须遵守一项约束：每个项目必须每 X 周（例如 2 周）产出令人兴奋且可演示的进展。如果一个项目在 X 周后最终无法进行演示，则必须至少搁置 X 周。

唯一的例外是「基础设施」项目，如果此类项目能够扩展在那些 X 周周期内可实现的项目范围，则允许消耗更多时间。

专注的软件开发工作是自我否定的↗

作者描述专注软件开发时出现的“隧道视野”：注意力被系统边界和代码问题占据，自我反思与创意减少，写作也更困难。他不确定该如何调整工作安排，并转述 David Chapman 的解释：常规编程往往围绕他人设计的 API 拼接，而创造性工作更可能让人感到内容由自己生成。

揭发内部腐败↗

Andy Matuschak 认为，研究者若无法预先知道解决问题的完整路线，就应留意意外数据和困难，因为突破可能藏在本想略过的异常处。他主张公开谈论工作中的真实挑战，而非把营销和探索隔离；诚实披露问题有助于形成奖励怀疑、反馈和自我修正的循环。
