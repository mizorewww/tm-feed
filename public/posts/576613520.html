我们在设计助记媒介[1]时的一个早期理论是，如果把第一章的内容复习几遍，第二章会更容易理解：复杂概念很难学习的部分原因是工作记忆容纳不下其组分[2]。

更进一步的话：

  1. 写后续章节时，不要当成单独成文的篇章来写，而是对先前章节所叙重点的专门补充。同时可以假定读者已经充分学习了这些材料。

  2. 每章写得短一些，避免工作记忆超负荷；章节之间的分隔可以充当「检查点」，通过检查点后再写新内容。

  3. 向读者建议何时阅读下一章，或是在章节列表里呈现，等着读者阅读，或是主动推送通知给读者。也许可以对后续章节施加限制，只有阅读完必须的章节才可以阅读本章。

  4. 写作时考虑更长的阅读时间轴。如果作者知道，读者读完第一章后，要等待两个月才能读第五章，作者与读者之间的关系可能发生很大改变。（大众媒介大多缺乏超过一天的创制时间维度[3]）

Execute Program 实现了这些概念中的前三个，其体验也很有策划感：

  1. Execute Program 的课程假定学习者对先前材料记忆牢固
  2. Execute Program 的课程相当短
  3. Execute Program 的课程只有在你成功复习其前置课程后才会解锁

这是助记媒介可调整为将创制经验逐步展开的形式[4]的一个可能实例，一种穿越时间的文本[5]。

可以联系渐进阅读，但作者对不同环节的创作控制更多。

Execute Program↗

这篇译文介绍 Gary Bernhardt 的 Execute Program：它把编程讲解与可执行练习结合，并用间隔重复系统安排回顾。作者列出其交互特点，包括课程按前置知识解锁、卡片要求实际运行程序、复习错误不作惩罚，以及进度更强调完成新课而非无限延长复习。

在你成功复习其前置课程之前，Execute Program 的课程不会解锁↗

作者解释，Execute Program 会锁住尚未满足前置条件的课节，只有依赖课程被阅读并近期复习后才解锁。这样作者可写出更聚焦、无需重讲前置内容的课程，但也形成过关式学习序列，与间隔重复按个体记忆状态灵活安排复习的方式存在冲突。

Execute Program 的卡片既是应用卡片，也是回忆卡片↗

作者比较助记媒介与 Execute Program 的学习卡片，指出后者以例题应用知识，看起来是应用卡；但若同一题干反复出现，答案逐渐依赖记忆，卡片便转为回忆卡。由此，程序性知识卡可能随重复变成陈述性知识卡，而陈述性知识也被包装成程序练习形式。
