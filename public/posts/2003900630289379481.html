https://www.executeprogram.com

Execute Program 提供由 Gary Bernhardt 制作的、关于编程工具的交互式课程。课程将讲解文字与可直接动手的编程题穿插呈现。类似于助记媒介[1]，该网站集成了一个间隔重复记忆系统[2]，用于随着时间推移重复课程任务。

  • 课程体验：
    • Execute Program 的课程根据读者的互动逐段展开正文[3]
    • 读者通过执行程序来回答 Execute Program 的交互卡片[4]
    • Execute Program 没有不可执行的卡片[5]
    • Execute Program 的卡片既是应用卡片，也是回忆卡片[6]
    • 多个例子可以使用同一段代码「preamble」——一种有用的领域特化
    • Execute Program 的课程相当短[7]
    • Execute Program 的 Python 课程有一个动态参考资料
  • 课程与系统结构：
    • 在你成功复习其前置课程之前，Execute Program 的课程不会解锁[8]
    • Execute Program 的课程假设你对先前材料有扎实的回忆[9]
    • 在 Execute Program 的复习中，错过的答案不会惩罚学生，除非他们「放弃」[10]
    • Execute Program 的进度机制强调完成新课，而不是延长回忆时长[11]

相关：助记文本可以在一段时间内分小段连载，根据读者的记忆情况排期[12]

Execute Program 没有不可执行的卡片↗

作者说明 Execute Program 的交互卡片要求读者实际执行代码来回答，因此该课程只包含可执行的“应用卡片”，不能容纳解释正则表达式概念等传统问答卡。文章以此指出，面向操作技能的练习模式不适合主要依赖概念分析的课程。

Execute Program 的卡片既是应用卡片，也是回忆卡片↗

作者比较助记媒介与 Execute Program 的学习卡片，指出后者以例题应用知识，看起来是应用卡；但若同一题干反复出现，答案逐渐依赖记忆，卡片便转为回忆卡。由此，程序性知识卡可能随重复变成陈述性知识卡，而陈述性知识也被包装成程序练习形式。

Execute Program 的课程根据读者的互动逐段展开正文↗

作者比较 Execute Program 与助记媒介：前者逐段解锁文字，读者完成交互卡片后才继续，阅读节奏一致、卡片更贴合流程，但自由滚动和略读空间较少。作者认为这种结构像一场只能回应的对话，互动仍由课程控制，因此不算由参与者行动主导的情景体验。

在 Execute Program 的复习中，错过的答案不会惩罚学生，除非他们「放弃」↗

这则产品设计笔记说明，Execute Program 的间隔重复练习曾因机器评分把拼写等小错判成失败而产生大量假阴性。SQL 课程因此改为允许多次作答，只要最终正确就不算失败，且不再以表现决定后续课节解锁；只有点击“放弃”查看答案时，系统才缩短该题的复习间隔。

助记文本可以在一段时间内分小段连载，根据读者的记忆情况排期↗

作者设想将助记文本拆成短章节，并依据读者对前文的记忆安排解锁或推送时间；后续章节应补充而非重复前文，短小单元也可降低工作记忆负担。文中以 Execute Program 的课程结构为例，讨论一种跨时间展开的交互式文本。

在你成功复习其前置课程之前，Execute Program 的课程不会解锁↗

作者解释，Execute Program 会锁住尚未满足前置条件的课节，只有依赖课程被阅读并近期复习后才解锁。这样作者可写出更聚焦、无需重讲前置内容的课程，但也形成过关式学习序列，与间隔重复按个体记忆状态灵活安排复习的方式存在冲突。
