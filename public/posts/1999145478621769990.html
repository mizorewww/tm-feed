Execute Program 的课程根据读者的互动逐段展开正文

#交互式学习#Execute Program#助记媒介#阅读体验#读者能动性

在 Execute Program 中，你无法一次性读完整个课程：你读一两段，然后按下「继续」按钮，接着又会出现一两段，随后你会遇到一张交互卡片。一旦你完成了这张卡片，下一部分的文本内容才会呈现出来。这是一个紧凑的输入/输出循环，具有稳定的节奏。

这种细粒度的循环与读书完全不同，读书时读者可以控制节奏和深度。在传统的在线书籍中，所有文本始终都是呈现出来的；唯一的互动就是滚动。滚动是连续的，而 Execute Program 的步骤是离散的，且在过程中系统会为你自动滚动。前者确实让人感觉明显更舒适。从这个意义上说，Execute Program 更像是在模仿一场对话，不过是一场你只能点头并照做的对话。参见交互是界面设计中的成本中心[1]。

但这种设计确实创造了一种高度一致的阅读体验。在助记媒介（Mnemonic medium）[2]中，你可以自由地滚动并通读全文。在「阅读模式」和「交互模式」之间切换需要你停止滚动，并去点击复习框。从这个意义上说，交互卡片在 Execute Program 中感觉比在助记媒介中更「契合」：Execute Program 课程的每一个「片段」，无论是阅读还是回答卡片，都需要互动，因此感觉比在助记文章中少了些「切换感」。

同样，在助记媒介中，读者有可能「跳过」复习区域，无论是无意还是有意的；这给读者制造了需要额外留意的状态。Execute Program 的课程是线性的；读者只需跟着流程走即可。

情景体验需要由参与者的行动控制[3]；那么 Execute Program 是一种情景体验（Enacted experience）[4]吗？不：情景体验需要由参与者的行动控制[5]。


Q. 在 Execute Program 中阅读课程文本的体验与阅读书籍文本有何不同？
A. 它会随着用户的互动逐段展开。你无法一次性阅读全部内容。

Q. 为什么交互卡片在 Execute Program 中感觉比在 Quantum Country 中更「契合」？
A. 在 Execute Program 中，阅读本身就需要互动，因此交互卡片不需要你切换成一种交互姿态。

Execute Program 的课程相当短↗

作者观察到 Execute Program 的课程通常只有几分钟：简短解释后立即操作，再通过交互卡片重复练习关键概念。他认为，读者能在体验中理解内容，使课程无需冗长讲解；这种短小、按互动展开的结构类似复习环节，也可视为情景体验或可执行书籍的初步形式。

读者通过执行程序来回答 Execute Program 的交互卡片↗

作者说明 Execute Program 的卡片要求学习者在嵌入式解释器中运行代码，系统按程序求值结果判定答案，而非逐字比对。因此答案可以有多种正确写法，交互更接近真实编程环境；复杂问题卡还让读者修改代码，使程序输出符合目标表达式。作者认为这种设计能把课程嵌入实际任务。

Execute Program↗

这篇译文介绍 Gary Bernhardt 的 Execute Program：它把编程讲解与可执行练习结合，并用间隔重复系统安排回顾。作者列出其交互特点，包括课程按前置知识解锁、卡片要求实际运行程序、复习错误不作惩罚，以及进度更强调完成新课而非无限延长复习。

助记文本可以在一段时间内分小段连载，根据读者的记忆情况排期↗

作者设想将助记文本拆成短章节，并依据读者对前文的记忆安排解锁或推送时间；后续章节应补充而非重复前文，短小单元也可降低工作记忆负担。文中以 Execute Program 的课程结构为例，讨论一种跨时间展开的交互式文本。

在你成功复习其前置课程之前，Execute Program 的课程不会解锁↗

作者解释，Execute Program 会锁住尚未满足前置条件的课节，只有依赖课程被阅读并近期复习后才解锁。这样作者可写出更聚焦、无需重讲前置内容的课程，但也形成过关式学习序列，与间隔重复按个体记忆状态灵活安排复习的方式存在冲突。

在 Execute Program 的复习中，错过的答案不会惩罚学生，除非他们「放弃」↗

这则产品设计笔记说明，Execute Program 的间隔重复练习曾因机器评分把拼写等小错判成失败而产生大量假阴性。SQL 课程因此改为允许多次作答，只要最终正确就不算失败，且不再以表现决定后续课节解锁；只有点击“放弃”查看答案时，系统才缩短该题的复习间隔。
