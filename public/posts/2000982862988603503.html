Execute Program 的课程相当短

Execute Program 的课程通常只有几分钟。你会读几段关于新概念的文字，立刻上手尝试，然后重复几次，以覆盖该概念的一些核心细节。然后就结束了。

这种简短在一定程度上是因为 Execute Program 的课程假设你对先前材料有扎实的回忆[1]，但我感觉交互式卡片的存在起了更大的作用。作者不需要花太多时间描述概念，因为读者马上就会亲身体验它。这与我写过的几个现象有关：

  • 它是对一种情景体验[2]的非常粗略的近似
    • （尤其是情景体验可以引导人们积极参与到赋能环境中[3]）
  • 在可执行书籍中也有类似效果
  • 在助记媒介卡片穿插在阅读过程中[4]所描述的一些影响

因此，这些课程在体验上其实很像复习环节：你可以在一次短暂的坐下来把它完成，并且它不会过度消耗你的注意力。课程与复习环节之间这种相似性，又会被两者交互模型的相似性进一步放大：Execute Program 的课程根据读者的互动逐段展开正文[5]。

Execute Program 的课程根据读者的互动逐段展开正文↗

作者比较 Execute Program 与助记媒介：前者逐段解锁文字，读者完成交互卡片后才继续，阅读节奏一致、卡片更贴合流程，但自由滚动和略读空间较少。作者认为这种结构像一场只能回应的对话，互动仍由课程控制，因此不算由参与者行动主导的情景体验。

Execute Program 的课程假设你对先前材料有扎实的回忆↗

Andy Matuschak 介绍 Execute Program 的课程设计：课程短而聚焦，默认读者能回忆前置知识；平台要求先复习前置课程再解锁新课，以减少重复内容和新课卡顿。作者询问 Gary Bernhardt 后得知，这种设计既符合其写作偏好，也由解锁机制强化。

Execute Program↗

这篇译文介绍 Gary Bernhardt 的 Execute Program：它把编程讲解与可执行练习结合，并用间隔重复系统安排回顾。作者列出其交互特点，包括课程按前置知识解锁、卡片要求实际运行程序、复习错误不作惩罚，以及进度更强调完成新课而非无限延长复习。

读者通过执行程序来回答 Execute Program 的交互卡片↗

作者说明 Execute Program 的卡片要求学习者在嵌入式解释器中运行代码，系统按程序求值结果判定答案，而非逐字比对。因此答案可以有多种正确写法，交互更接近真实编程环境；复杂问题卡还让读者修改代码，使程序输出符合目标表达式。作者认为这种设计能把课程嵌入实际任务。

在你成功复习其前置课程之前，Execute Program 的课程不会解锁↗

作者解释，Execute Program 会锁住尚未满足前置条件的课节，只有依赖课程被阅读并近期复习后才解锁。这样作者可写出更聚焦、无需重讲前置内容的课程，但也形成过关式学习序列，与间隔重复按个体记忆状态灵活安排复习的方式存在冲突。
